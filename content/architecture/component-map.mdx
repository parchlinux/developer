# Component map

Every Parch component, its upstream, and its source. Keep this map honest:
it is how contributors figure out where a change belongs.

## Consumed from upstream, unmodified

- Arch Linux repositories `core` and `extra` (the bulk of any installed
  system).
- The Linux kernel, systemd, mkinitcpio, pacman.
- KDE Plasma, GNOME, XFCE, Hyprland, and their applications.
- Calamares upstream (the Parch flavor packages configuration on top).

## Parch-modified upstream

| Upstream | Parch package | Why |
|---|---|---|
| archiso | `archiso` 99-1 in world | Parch build patches and defaults |
| Calamares | `calamares` 3.4.3-8 in world | Parch modules and fixes |

When a Parch-modified package drifts too far from upstream, the maintenance
cost shows up at every upstream update. The decision framework (patch
downstream, fix upstream, or fork) is in
[Packaging](/packaging/pkgbuild-reference/) and
[Distribution development](/distribution/).

## Ownership boundaries

<Checklist>
  - Upstream bug: file it upstream; Parch tracks the fix.
  - Parch packaging bug: fix in the PKGBUILD or the component repo.
  - Unclear: ask in the component repo's issue tracker before patching.
</Checklist>
