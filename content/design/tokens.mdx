# Design tokens

Tokens are named design decisions. Components and mock apps consume tokens
only, never raw hex values, so a theme change propagates everywhere at once.
The portal's own stylesheet is the canonical token file; applications map these
semantics onto their toolkit equivalent (GTK `@accent_color`, Qt palette roles).

## Brand colors

The Parch identity is a teal→blue gradient with a purple secondary accent,
drawn from the [parchlinux.com](https://parchlinux.com) brand.

Brand colors are for identity moments: the logo, hero surfaces, active accents.
They are **not** the default button color everywhere, semantic roles below
keep interfaces calm.

## Semantic colors

Semantic tokens adapt to light and dark automatically. Never use a semantic
token for the wrong role (for example, `--danger` is only for destructive
actions and errors).

## Typography

Parch uses **Saira** for Latin UI text, **Estedad** for Persian (RTL) text,
and **JetBrains Mono** for code and identifiers. All three are open fonts.

Persian text uses Estedad at the same sizes with 1.05× line-height for the
taller Arabic-script letterforms; see [RTL and Persian typography](/hig/rtl-and-persian/).

## Motion

Motion is feedback, not decoration. Durations: 150ms for hovers and state
changes, 250ms for enters/exits, both on the soft-out curve
`cubic-bezier(0.2, 0.8, 0.2, 1)`. Everything respects
`prefers-reduced-motion`.

<Callout kind="tip" title="Indeterminate progress">
  The one looping animation in the system is the indeterminate progress sweep ,
  1.6s on the same soft-out curve.
</Callout>

## Focus and accessibility

Focus is always visible: a 2px `--accent` ring with 2px offset. Contrast
ratios for text and interactive states meet WCAG 2.1 AA in both themes.
See [Accessibility](/hig/accessibility/) for the full rules.
