# Design System

The Parch design system is the working implementation of the [Parch Human
Interface Guidelines](/hig/). Every component on these pages is live: rendered
with the same tokens, styles, and behavior that first-party Parch applications
are specified to use. If the HIG and this system disagree, this system wins.

## Principles

<Checklist>
  - **One token source.** Components never hardcode colors or sizes; they read
    semantic tokens (`--accent`, `--surface-2`, …) that adapt to light and dark.
  - **Respect the toolkit.** The design system defines Parch's shared language;
    GTK/libadwaita and Qt apps keep their toolkit's native patterns and map
    these intents onto them (see [Platform integration](/hig/platform-integration/)).
  - **Keyboard complete.** Every interactive component is reachable and
    operable by keyboard, with visible focus.
  - **RTL aware.** Layouts mirror in right-to-left locales; see
    [Localization & Accessibility](/localization/).
</Checklist>
