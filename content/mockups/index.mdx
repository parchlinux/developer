# App Designs

These mock applications demonstrate how Parch software should look and
behave. Each one is assembled from the same design tokens and components shown
in the [Design System](/design/), nothing here is a disconnected mockup. Use
the theme switch on every mock to check light and dark.

Two kinds of entry live in this gallery:

- **First-party app**, the application exists (e.g. Pastor, parch-welcome);
  the mock illustrates its design direction and interaction patterns.
- **Design concept**, a proposed design that does not ship today; it shows
  the HIG applied to a surface Parch has not built yet.

<Callout kind="important" title="Design references, not claims">
  Mocks marked “design concept” are not announcements of shipping software.
  They exist so designers and developers have a concrete target, and so the
  HIG rules have full-window examples.
</Callout>

## Toolkit reality

Mocks represent Parch's shared design language. When an application is built
with GTK/libadwaita or Qt, it keeps its toolkit's native widgetry, header
bars, shortcuts, and menus map to toolkit equivalents. See
[Platform integration](/hig/platform-integration/) for the mapping rules.
