# Navigation patterns

## Choosing a pattern

<SpecTable
  columns={["Pattern", "Use when", "Example"]}
  rows={[

    ["Tabs", "2–5 peer views, flat", "Store: Explore / Installed / Updates"],

## Rules

<Checklist>
  - The current destination is always visible and marked (accent + weight).
  - Navigation state survives app restarts where meaningful (reopen the last
    pane).
  - Deep links work: every view reachable by navigation is reachable by URL
    or desktop action.
  - Back/forward behave like a browser in document-like apps; in apps with a
    sidebar, back steps through view history.
  - Never nest tabs inside tabs; nest a list or sidebar instead.
</Checklist>

## Sidebar specifics

- Sections are icon + label; icon-only sidebars need tooltips and are
  reserved for narrow utility windows.
- The sidebar scrolls independently of content.
- On narrow windows it collapses into a drawer with the same tree and order.
